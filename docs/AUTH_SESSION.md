# Срок жизни входа и мобильная сеть

Что относится к жалобе «на мобильном интернете разлогинивает, хочу до 30 дней».
Половина решается кодом фронта (сделано), половина — настройками Supabase Auth
(GoTrue) на сервере: **из репозитория они не задаются**, их надо править там,
где поднят `supabase.gottland.ru`.

---

## 1. Что уже сделано в коде (клиент)

| Файл | Что изменилось |
|---|---|
| `frontend/src/supabase.js` | fetch с таймаутом 20 с и 2 ретраями. У браузерного fetch таймаута нет: на мобильной сети запрос за токеном не падает, а **висит** — и вместе с ним висит всё приложение. |
| `frontend/src/authStorage.js` | Сессия хранится в localStorage **и зеркалится в IndexedDB**. Дефолтный localStorage на телефоне выселяется (iOS ITP), и вместе с ним улетает refresh-токен. |
| `frontend/src/context/AuthContext.jsx` | Сетевой сбой больше **не считается выходом**. Пользователь обнуляется только по явному `SIGNED_OUT`/`USER_DELETED` или когда сессии реально нет. |
| `frontend/src/api.js` | 401 → один прозрачный refresh и повтор запроса; таймауты; ретраи для GET. |

Клиент теперь **не теряет** и **умеет обновить** токен. Но сколько живёт сам
вход — решает только сервер.

---

## 2. Что надо выставить на сервере (GoTrue)

Правится в окружении контейнера `auth` (`supabase/docker/.env` или
`docker-compose.yml` вашей инсталляции), затем `docker compose up -d auth`.

### 2.1. Собственно «30 дней»

Срок входа задаёт **refresh-токен**, а не JWT. По умолчанию он бессрочный —
сессия живёт, пока ей пользуются. Ограничивают её две переменные:

```env
# Жёсткий потолок возраста сессии. 30 дней = 720h.
# ПРОПУСТИТЬ переменную = «никогда не истекает». Ноль ставить нельзя:
# значение 0 не проходит валидацию, контейнер не поднимется.
GOTRUE_SESSIONS_TIMEBOX=720h

# Выход по бездействию: сессия умирает, если её столько не обновляли.
# Для «30 дней без повторного входа» — либо 720h, либо не задавать вовсе.
GOTRUE_SESSIONS_INACTIVITY_TIMEOUT=720h
```

> **Проверьте это в первую очередь.** Если сейчас там стоит что-то короткое
> (`24h`, `8h`) — вот он и есть «выкидывает очень быстро», и никакой код на
> фронте это не переспорит.

Заодно убедитесь, что не включено `GOTRUE_SESSIONS_SINGLE_PER_USER=true`:
с ним вход с телефона гасит сессию на компьютере и наоборот.

### 2.2. Ротация refresh-токенов — главный подозреваемый на мобиле

```env
GOTRUE_SECURITY_REFRESH_TOKEN_ROTATION_ENABLED=true
GOTRUE_SECURITY_REFRESH_TOKEN_REUSE_INTERVAL=30   # секунды, дефолт 0
```

Механика отказа: клиент шлёт refresh-токен, сервер его **уже отозвал и выдал
новый**, но ответ до телефона не доехал (лифт, пересадка LTE↔Wi-Fi). На руках у
клиента остаётся мёртвый токен → следующий заход = разлогин. При
`REUSE_INTERVAL=0` это происходит с первого же потерянного ответа.

Интервал переиспользования даёт окно, в котором повтор со старым токеном вернёт
ту же пару. **30 секунд** — разумный минимум для мобильного клиента. Ретраи в
`supabase.js` работают именно в паре с этой настройкой.

Если ротация у вас выключена (`false` — дефолт self-hosted), эта проблема не
ваша, трогать не надо.

### 2.3. JWT expiry — не про 30 дней

```env
GOTRUE_JWT_EXP=3600
```

Это срок **access-токена**, а не входа. Поднимать его до суток можно (реже
обновления → меньше поводов сорваться на плохой связи), но помните: бэкенд
(`backend/app/auth.py`) проверяет подпись и `exp`, списка отзыва у него нет —
украденный токен будет жить весь этот срок. Оставить 1 час безопаснее, и с
починенным обновлением он пользователю не мешает.

---

## 3. Как проверить, что настройки доехали

```bash
# срок сессии/ротацию наружу GoTrue не отдаёт — смотрим переменные контейнера
docker compose exec auth env | grep -E 'GOTRUE_(SESSIONS|SECURITY_REFRESH|JWT_EXP)'
```

Проверка «в поле»: войти с телефона, включить авиарежим на минуту прямо во время
работы, выключить — приложение должно остаться залогиненным и просто дообновить
токен, а не увести на `/login`.
